Start with a usable brief

The details that help us direct you to the right data route.

You do not need a fully written specification to begin. A few practical details will help us decide whether a published page, a new collection programme, annotation work, or a governance discussion is the best next step.

What the model needs

  • Data type and intended model or product use
  • Languages, domains, scenes, tasks, or participant profile
  • Whether you need new data, existing data, or both
  • Key exclusions or safety requirements

How the data should work

  • Target volume and preferred file or metadata format
  • Annotation or transcription requirements
  • Quality criteria and evaluation needs
  • Desired delivery route and project timeline

What needs to be reviewable

  • Rights, consent, governance, or compliance expectations
  • Buyer, vendor, or due-diligence questions
  • Expected processing and delivery locations
  • Any potential sensitive-data or re-identification concerns

What happens next

  • We review the information you have
  • We identify the relevant published or commissioned route
  • We clarify the missing operational questions together
  • We scope an appropriate next conversation

Frequently asked questions

Using the Data types hub.

Does every data type have a ready-made catalogue?

No. Most BSG DataWorks projects are commissioned. The published pages show the areas you can explore now; a commission brief is the right route when your data needs to reflect a specific language, market, environment, contributor profile, model task, or delivery requirement.

What should I do if I need a data type that is not listed?

Start a dataset brief with the closest data type and explain the intended model use. If the work is within our collection, annotation, or advisory scope, we will help identify the practical next questions.

Can you work with data we already have?

Yes. The annotation and labelling route is for teams that already have source material and need a clear schema, guidelines, quality checks, and delivery structure for a specific AI use case.

How do collection and compliance relate to a data type?

The modality tells you what kind of data a model needs. Collection and compliance support help structure how the project is specified, documented, and reviewed. The appropriate scope depends on the actual project facts.

Can I use this page to request pricing?

Yes. Tell us the data type, model use, approximate volume, timing, and procurement or licensing context if known. If you are still scoping, send what you have and we can clarify the remaining questions on a call.
